# PMS V2 最终问题修复设计

## 目标

依据 `芋道系统_Bug需求反馈清单_V2.xlsx` 和 2026-07-30 浏览器回归报告，修复仍未满足或被基础故障阻塞的项目管理功能，并通过自动化测试、构建及真实浏览器流程验证后推送 GitHub。

## 已确认业务规则

- 模板实例化只复制阶段结构和任务名称。
- 模板任务的计划开始、计划结束、责任人、协助人和进度全部置空或初始值，不继承模板实例数据。
- 日期字段统一显示为 `YYYY-MM-DD`；包含时间的记录统一为 `YYYY-MM-DD HH:mm`。
- “本周到期”按 Asia/Shanghai 时区的周一 00:00 至周日 23:59:59 计算。
- 工期按自然日包含首尾日计算，即 `结束日期 - 开始日期 + 1`。
- 已完成任务进度必须为 100；驳回时恢复提交审核前的业务状态和进度。

## 修复范围

### 1. 项目列表与创建

- 定位列表显示 0 项目的接口参数、权限或状态过滤根因，统一列表与详情可见性规则。
- 卡片视图提供项目复选框，使批量归档按钮具有明确可操作前置条件。
- 移除阶段筛选。
- 修复模板卡片阶段/任务数量和模板明细加载。
- 创建向导中的项目经理和成员关系采用显式规则：项目经理自动成为成员，不允许在仍任项目经理时直接删除。
- 移除偏移日期和批量设工期操作。
- 防止新增或编辑任务覆盖其他任务责任人。

### 2. 日期、工期与甘特图

- 修复“本周到期”的周范围计算。
- 抽取并复用日期显示函数，消除 `MM-DD` 混用。
- 任务日期必须同时为空或同时有值，且结束日期不得早于开始日期。
- 工期使用包含首尾日的自然日公式。
- 阶段甘特图日期取子任务最早开始和最晚结束；无有效日期的阶段不伪造 `2026-01-01`。

### 3. 任务、质量、文档和审批

- 清理任务详情冗余字段展示；保证完成状态与进度一致。
- 质量问题补充编辑操作并修复分类、责任人和发现日期映射。
- 输出物上传成功后立即持久化；关闭并重开弹窗重新查询服务端数据。
- 项目文档聚合当前项目所有任务输出物，显示任务、上传人和上传时间。
- 审核驳回使用后端实际支持的路由，保存驳回状态并触发钉钉通知；通知失败不得回滚审核结果，但必须留痕。
- 变更审批通过后自动执行目标变更，使用后端支持的 HTTP 方法，保证幂等并记录执行结果。

## 数据流与错误处理

- 页面查询参数先标准化，再调用 API；列表和详情使用同一租户及权限上下文。
- 日期计算集中到纯函数并以单元测试覆盖周跨月、跨年、空日期和逆序日期。
- 上传、审核和变更执行以服务端持久化结果为准，前端临时状态只负责交互，不作为事实来源。
- API 失败显示可理解的错误消息，并保留原数据；禁止静默失败或用默认日期掩盖错误。

## 测试策略

- 前端：Vitest 覆盖日期、阶段汇总、模板实例化和状态进度规则；组件测试覆盖按钮显隐及表单校验。
- 后端：JUnit 覆盖项目可见性、审核驳回、变更执行和附件聚合服务。
- 集成：执行前后端现有测试、类型检查和生产构建。
- 浏览器：按 22 条清单重新验证，重点保存“输入值、保存响应、列表回显、详情或甘特图回显”证据。
- 权限：至少使用项目负责人和非负责人两个账号；账号缺失时明确标记阻塞，不伪报通过。

## Git 与部署边界

- 在 `codex/pms-v2-final-fixes` 分支开发，保留服务器未提交的 `application-local.yaml`。
- 每批修复独立提交，完成验证后推送 GitHub 并创建 PR；不强推、不自动合并主分支。
- GitHub 推送不等于服务器部署。只有用户明确要求部署时，才在备份和可回滚前提下更新运行环境。
